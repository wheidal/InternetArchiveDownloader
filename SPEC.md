# iafetch: Requirements and Specification

*Draft 0.3, 2026-10-28. Phase 1 is under way: see §9.* The research behind this spec (terms of use, API limits, collection survey, item anatomy) is in [RESEARCH.md](RESEARCH.md). The review of existing downloaders is in [PRIOR_ART.md](PRIOR_ART.md). Requirements taken from it are marked *(prior art)*.

## 1. Overview

`iafetch` finds, downloads, verifies and files media from the Internet Archive (archive.org): music, audiobooks, radio, films, TV, books, magazines, comics, software, images and datasets. It is deadfetch generalized. One polite, verifiable download engine is shared by every media type, and a **handler** for each kind of media decides which files to take, how to name and tag them, and where they go.

### Goals

1. **Be a model citizen on archive.org.** Every rule in §3 is enforced by the engine, not left to the user.
2. **Get the right files.** Take originals, or the one useful derivative, never the Archive's generated byproducts, and never the same bytes twice.
3. **Verify everything.** Every file is checked against the size and MD5 that archive.org lists.
4. **Produce a library, not a dump.** Each media kind lands in a layout its player understands (Jellyfin, a music player, Calibre, an emulator front end), with tags or sidecar metadata.
5. **Run unattended.** A queue that resumes after interruptions, background runs, and status and reporting, as in deadfetch.
6. **Never guess silently.** When post-processing can't decide (an unparseable episode list, a track list that doesn't match), stop with an editable plan, the deadtag way.

### Non-goals

- **Anything restricted:** borrowable (lending library), stream-only, print-disabled, or `private` files. No DRM removal, no login sharing.
- **The Wayback Machine** and web crawls (WARC/CDX are a different system).
- **TV News Archive** clips (restricted).
- **Uploading** to archive.org.
- **Mirroring whole collections** at scale. Large jobs are possible but throttled, and the tool tells the user to contact the Archive first (§3.6).
- **Redistribution.** The tool serves a personal or research library.

## 2. Relationship to DeadShowTagger

- **Reused as a library.** deadfetch's `download.py` (Throttle, resumable MD5-checked `_fetch_file`, `Retry-After` handling) and `catalog.py` (scrape-API paging) are the core of the engine. They should move into a shared package (§10, Q2) instead of being copied.
- **deadtag becomes the first handler.** `GratefulDead` items are handed to deadtag's existing `plan`/`process` pipeline unchanged, so its behavior and its 347 tests stay as they are.
- **The general live-music handler** (etree outside GD) reuses deadtag's info-.txt parser, matcher and plan file, minus the GD-specific heuristics.
- **The same conventions carry over:** TOML config in `~/.config/iafetch/`, an inbox then a library, an archive folder, plan JSON with `"approved"`, a summary at the end of a run, `--dry-run`, and a library folder that must already exist (protects against an unmounted NAS).

## 3. Respectful-use requirements

These are **hard requirements**. Defaults are fixed in code. Users may make them *stricter* in config. Making them looser is limited to the stated ceilings.

### 3.1 Identification

- **R1.** Every request carries `User-Agent: iafetch/<version> (+<project URL>; personal collection)`. Per archive.org's bots page, a run started by an AI agent appends the model (`; agent=<model-id>`).
- **R2.** The User-Agent is set in one place, and no code path can make a request without it (tested).

### 3.2 Pacing and concurrency

| Setting | Default | Ceiling | Source |
| --- | --- | --- | --- |
| Concurrent file downloads | **1** | **4** | bots page: `parallel -j4 --delay 1` |
| Delay between download starts | 2 s | at least 1 s | bots page, deadfetch |
| Delay between API calls (search, metadata) | 1 s | at least 1 s | deadfetch, plus the 429 seen during research |
| Bandwidth cap | 4 MB/s | user's choice (`none` allowed) | deadfetch |
| Ramp-up | concurrency starts at 1 and rises by 1 per 10 clean files, up to the setting | n/a | blog: "start slowly, and ramp up" |

- **R3.** One shared rate limiter (token bucket) covers every request to `*.archive.org`, including API calls, file downloads and redirects to datanodes. Handlers can't bypass it.

### 3.3 Backing off and stopping

- **R4.** On `429` or `503`, wait for `Retry-After` (or 30 s × attempt if it's missing, with ±20% jitter). Concurrency drops to 1 for the rest of the run. **The backoff is global:** one worker's 429 pauses every worker. *(prior art: grab-ia)*
- **R4a. No segmented downloads.** One connection per file. Every open connection counts toward the concurrency ceiling. *(prior art: what to avoid)*
- **R4b. 401, 403 and 404 are permanent:** never retried. *(prior art: Archive Station)*
- **R5. Circuit breaker.** After 5 consecutive 429s or 403s, or 3 failed attempts on one file, **the run stops** and says why. When it's blocked (403 on requests that worked before), it prints the blog's advice: don't restart, write to info@archive.org. It never rotates IPs, User-Agents or accounts.
- **R6.** Other 5xx and network errors are retried up to 3 times with exponential backoff (2, 8, 32 s), resuming the partial file.
- **R7.** A 404 or "item is dark" counts as gone, not as an error to retry. The item is marked `unavailable` in the queue.

### 3.4 Asking less of the servers

- **R8. Enumeration goes through the scrape API** (cursor, `count` 1,000 to 10,000, only the fields needed). Never page `advancedsearch.php` past its 10,000-result limit.
- **R9. Cache metadata.** `/metadata/<id>` responses are cached locally (default TTL 7 days, `--refresh` overrides). Search results are kept as a catalog per saved query, refreshed incrementally.
- **R10. Never fetch the same thing twice.** Skip a file whose local size and MD5 already match. Resume partial files with `Range`. Pick one route per item: per-file, the item ZIP, or the torrent.
- **R11. Skip generated byproducts by default:** Spectrogram, Columbia Peaks, Essentia, Thumbnail, Animated GIF, hOCR/chOCR, OCR indexes, Scandata, logs, `*_meta.sqlite`, and the CAR/Storj triggers. Handlers can opt specific ones back in.
- **R12. Torrent offload.** For items over a configurable size (default 20 GB), offer `_archive.torrent` handed to an external client (Transmission or qBittorrent via a watch folder) instead of HTTP. Off by default; the engine still verifies the files afterwards.
- **R13.** Never request a robots-disallowed path (`/control/`, `/report/`).
- **R13a. Don't inflate view counts.** Downloads send `cnt=0`, as the official library does by default. Configurable, default on. *(prior art: internetarchive)*
- **R13b. On-the-fly derivatives** (EPUB, MOBI, DAISY, MARCXML, which aren't in `_files.xml` and are generated per request) are fetched only when a handler or the user explicitly asks. *(prior art: internetarchive)*
- **R13c. Transfer schedule (optional):** weekday time slots with an alternate bandwidth cap or a pause outside them. *(prior art: Archive Station)*

### 3.5 Access and rights

- **R14. Never attempt restricted content.** Search adds `-access-restricted-item:true -collection:stream_only -collection:inlibrary -collection:printdisabled` to every query. Files marked `private` are always skipped. LCP/ACS-encrypted formats are never selected.
- **R15. Credentials are optional** and only ever the user's own. They're read from the standard `ia.ini` (`~/.config/internetarchive/ia.ini`) and used only for access that account already has. They're never logged or written to sidecars.
- **R16. Record rights.** Each finished item gets an `iafetch.json` sidecar with the identifier, source URL, `licenseurl`, `rights`, `possible-copyright-status`, the download date and checksums. Queue listings and the end-of-run summary show the license, and **"no license declared"** is shown plainly.
- **R17. Don't store personal data** beyond what's needed. Ratings and review *counts* may be used for ranking (as deadfetch does). Reviewer names, review text and uploader emails aren't stored.
- **R18. First-run notice.** A one-time short statement of the terms ("scholarship and research … noninfringing or fair use … your responsibility") that the user acknowledges. Stored in config.

### 3.6 Large jobs

- **R19.** Before a run, iafetch estimates the total bytes and item count. Above **500 GB or 10,000 items** it warns, suggests contacting info@archive.org (per the blog), and requires `--large-job` to go ahead.
- **R20.** Disk-space guard, as in deadfetch: stop before the target drive would fall under a reserve (default 20 GB).

## 4. Functional requirements

### 4.1 Discovery

- **F1. Search:** free text and field filters (`collection`, `mediatype`, `creator`, `date`/`year`, `subject`, `language`, `licenseurl`), sorted by downloads, rating, date or title. Results show the identifier, title, kind, size and license.
- **F2. Browse:** list a collection's sub-collections and items (e.g. `iafetch browse etree`, `iafetch browse classic_tv`).
- **F3. Saved catalogs:** a query can be saved as a named local catalog (e.g. all `netlabels` CC-BY) and refreshed incrementally, the way deadfetch's catalog is.
- **F4. Item inspection:** `iafetch show <id|URL>` prints the metadata, the file list grouped as original or derivative (with what the handler would select), the total size, the license, and which handler applies.
- **F5. Input forms:** accepts identifiers, `archive.org/details/<id>` URLs, `archive.org/download/<id>/<file>` URLs, and a text file of either.

### 4.2 Selection

- **F6. Handler choice:** first match among a collection rule (e.g. `GratefulDead` → deadtag, `librivoxaudio` → audiobook), then a mediatype rule, then the generic handler. The user can override with `--as <handler>`.
- **F7. File selection** is the handler's default profile, adjustable with `--format` (archive.org format names, e.g. `"24bit Flac"`, `"h.264"`), `--glob`, `--exclude`, and `--originals`/`--all`.
- **F8. Partial items:** select by episode, issue or track inside multi-part items (`--files 'S01E*'`, `--episodes 1-10`, `--issues 260-270`).
- **F9. Quality preference** per handler: e.g. video `original` / `h264` / `smallest`; audio `lossless` / `mp3`; text `pdf` / `epub` / `both`.

### 4.3 Queue and runs

- **F10.** A persistent queue (`add`, `list`, `remove`, `retry`, `clear`) shows each entry's size and the free space at its destination.
- **F11.** `get` downloads the queue in order. It supports `--limit N`, `--max-size`, `--rate`, `--dry-run`, `--no-process` and `--background`.
- **F12.** `status` (from another terminal) and an optional local dashboard show the current item and file, speed, ETA and the queue. The deadfetch dashboard is generalized.
- **F13.** Interrupt-safe: kill it at any point, and the next `get` resumes from partial files.
- **F14.** A run log is appended, plus an end-of-run summary grouped as DONE / NEEDS REVIEW / UNAVAILABLE / FAILED.

### 4.4 Download and verification

- **F15.** Files are written to `<inbox>/<identifier>.partial/` and moved into place only once every selected file has passed its MD5 and size checks.
- **F16.** `_meta.xml` and `_files.xml` are always kept with the item, as the record of what was downloaded.
- **F15a. Resume safely** *(prior art: Archive Station, john-corcoran)*:
  - Send `Accept-Encoding: identity`.
  - On a `206`, require a `Content-Range` whose start equals the local offset and whose total equals the metadata size. Otherwise discard the partial file.
  - A `200` to a range request means start over.
  - A `416` means discard the partial file and retry once from zero.
  - Flush every chunk so a killed process resumes from the bytes on disk.
- **F15b. File names are untrusted:** reject any path that resolves outside the item's folder, and sanitize names for the target filesystem (NAS shares). *(prior art: internetarchive)*
- **F15c. Verify with SHA-1 when listed, else MD5.** Never hash-check `_files.xml` against itself. Report the count of `private` files that were skipped.
- **F15d.** A full disk (`ENOSPC`) **pauses** the queue rather than failing the item.
- **F17.** `iafetch verify [path]` re-checks a library item against its sidecar. Tagging and renaming change file hashes, so the sidecar records **both** archive.org's checksums for the originals **and** checksums of the processed files. For FLAC it uses the STREAMINFO audio MD5, which survives retagging. `--anywhere` matches checksums regardless of path. *(prior art: john-corcoran `--nopaths`)*
- **F17a. `iafetch refresh [item|library]`** re-reads current metadata, diffs it against the sidecar, and lists added, changed and removed files (a takedown shows as "removed"). The user chooses what to fetch. *(prior art: Archive Station)*

### 4.5 Post-processing (handlers)

- **F18.** Each handler implements `select(item) → files`, `plan(item, files) → Plan`, and `process(plan) → library paths`. Plans are JSON with `"approved"`, `"review"` and `"warnings"`, exactly like deadtag.
- **F19.** A handler that can't build a confident plan writes it as needing review and moves on. `--batch` accepts its best guesses and records them under `resolved_by`.
- **F20.** Output names come from templates (`{creator}`, `{title}`, `{year}`, `{date}`, `{series}`, `{season}`, `{episode}`, `{identifier}`, …) set per handler in config.
- **F21.** Each library item keeps `iafetch.json` (R16), and the original downloaded files are archived or deleted per the config (the deadtag archive-folder model).

## 5. Architecture

```
iafetch/
  net.py        one HTTP client: User-Agent, shared token bucket, Retry-After, circuit breaker (R1-R7, R13)
  api.py        scrape / advancedsearch / metadata wrappers, metadata cache (R8, R9)
  catalog.py    saved queries, incremental refresh
  select.py     file filters: originals/derivatives, junk list, formats, globs (R10, R11, F7-F9)
  download.py   resumable, verified file fetch; staging; torrent hand-off (from deadfetch)
  queue.py      persistent queue and run state (SQLite)
  rights.py     restriction filters, license summary, sidecar (R14-R18)
  handlers/
    base.py       Handler interface and Plan type
    generic.py    mirror the item as-is, flattened, with sidecar
    livemusic.py  etree (shares deadtag's parser)
    deadtag.py    adapter to DeadShowTagger for GratefulDead
    music.py      netlabels, 78rpm, audio_music albums
    radio.py      old-time radio and podcast-style series
    audiobook.py  LibriVox and spoken word
    video.py      films and TV
    texts.py      books, magazines, comics
    software.py   DOS, console, arcade
    images.py
  cli.py, tui/ (later), dashboard/
```

- **Python 3.11+**, standard library for the engine (as deadfetch). The `mutagen`, `Pillow`, `ffmpeg`, `flac` and `ebook-meta` dependencies are optional and per handler. A handler whose tools are missing says so and falls back to `generic`.
- **SQLite for state:** queue, catalog, metadata cache, run history. deadfetch's JSON files suit one collection; a general tool will track tens of thousands of items.
- **The handler registry** is ordered and configurable, so the user can map their own collections to handlers.

## 6. Handlers by media kind

The phase is the suggested build order (§9).

### 6.1 generic (P1)
Downloads the selected originals into `<library>/<kind>/<identifier>/`, with `_meta.xml`, `_files.xml`, the item tile as `folder.jpg`, and the sidecar. The fallback for every kind, and enough on its own for **data** (datasets) and **images**.

### 6.2 deadtag (P1)
`collection:GratefulDead` → the existing deadfetch ranking and deadtag pipeline. This proves the handler interface against working code.

### 6.3 livemusic: etree (P2)
- **Select:** FLAC or SHN, the info `.txt`, `.md5`/`.ffp`. Prefer 16-bit FLAC over 24-bit unless configured otherwise. Skip MP3/Ogg derivatives.
- **Rank sources** per artist and date (rating × review count, source type SBD > MTX > AUD) by generalizing `deadfetch/rank.py`.
- **Process:** parse the info .txt setlist (deadtag parser), convert SHN to FLAC, tag (`ARTIST`, `ALBUM` = `{date} {venue}`, `DATE`, set and segue markers), file under `{artist}/{year}/{date} {venue} [{source}]`.
- **Review cases:** the same as deadtag's (more titles than files, and so on).

### 6.4 music: netlabels, 78 rpm, albums (P2)
- **Netlabels:** take FLAC if present, else the MP3 originals. Never both the album ZIP and the tracks. Files are usually already tagged; fill in what's missing from metadata, add the cover, and write `COPYRIGHT`/`LICENSE` from `licenseurl`. Layout `{creator}/{year} - {title}/`.
- **78 rpm (georgeblood):** take the **restored 24-bit FLAC** and the **TIFF label scan**. Skip the 600 MB raw-transfer ZIP unless `--raw` is given. Tag from `creator`, `title`, `publisher`, `publisher-catalog-number` and `date`. Convert the label scan to `cover.jpg` and embed it. Optionally downsample to 16-bit/44.1 kHz. Layout `78rpm/{creator}/{title} ({publisher} {catalog})`.

### 6.5 radio: old-time radio and series audio (P2)
- One item holds a whole series (Gunsmoke: 480+ episodes). Selection is **per episode** (F8).
- Parse episode dates, numbers and titles from file names (OTRR names like `Gunsmoke 52-04-26 (001) Billy the Kid.mp3`). An episode that doesn't parse goes to review.
- Tag (`ALBUM` = series, `TITLE`, `DATE`, `TRACKNUMBER`) and file under `{series}/{year}/`. Optionally write a podcast-style RSS feed so a podcast app can play the library.

### 6.6 audiobook: LibriVox and spoken word (P3)
- If an `.m4b` exists, take it alone (it already has chapters). Otherwise take the chapter MP3s and **build an M4B with chapters** via ffmpeg (or [m4b-tool](https://github.com/sandreas/m4b-tool) if it's installed), with chapter titles from the item JSON or the file names.
- Tag author, title, narrator (LibriVox readers are listed in the JSON) and language. Layout `{author}/{title}/`, which suits Audiobookshelf.

### 6.7 video: films and TV (P2)
- **Films:** choose the original (MPEG2/MPEG4/QuickTime) or the `h.264` MP4 derivative per the quality setting (default `h264`: it plays everywhere and is much smaller). Take SubRip/WebVTT subtitles. Skip thumbnails.
- **TV:** parse `SxxEyy` and titles from file names (as in `get-smart`). Select episodes per F8.
- **Output for Jellyfin/Plex:** `Movies/{title} ({year})/{title} ({year}).mp4` with `.srt` sidecars, a `movie.nfo` built from the metadata (title, year, plot from `description`, director, runtime) and `poster.jpg` from the item tile. Series go in `TV/{series}/Season {ss}/{series} S{ss}E{ee} - {episode title}.mp4` with `tvshow.nfo`. This ties in with your Jellyfin setup.
- **Review cases:** episode numbers missing or duplicated, or no year for a film.

### 6.8 texts: books, magazines, comics (P3)
- **Scanned books:** default to the **Text PDF** (searchable) and/or the **EPUB** per config. Skip the JP2 page images unless `--scans` is given. Write Calibre-compatible `metadata.opf` (title, creator, date, publisher, language, ISBN, OCLC, Open Library IDs). Layout `{creator}/{title} ({year})/`.
- **Gutenberg:** take the HTML (with images) or the plain text per config.
- **Magazines:** one item is a whole run. Select issues per F8 and file under `Magazines/{title}/{year}/`.
- **Comics:** take CBZ/CBR and write `ComicInfo.xml`. Never the PDF derivative of a CBZ.

### 6.9 software: DOS, console, arcade (P4)
- Keep the ROM or program ZIP **exactly as published** (an arcade ROM set only works with the matching MAME version; record `emulator` and `emulator_ext` in the sidecar).
- Layout by platform for front ends: `Games/{platform}/{title} ({year}).zip`, with the emulator screenshot as box art and an optional LaunchBox/ES-DE gamelist entry.
- **Rights:** most software items have no license. The summary says so for each one.

### 6.10 images (P4)
Generic handling, plus `description`, `creator`, `date` and `subject` embedded as XMP/EXIF (via exiftool if present), and a layout of `Images/{collection}/{identifier}/`.

## 7. Configuration (sketch)

**Everything iafetch writes goes under one root folder, `/mnt/synology/InternetArchive`.** Each kind of media gets its own subfolder, and so do the inbox and the archive of originals. It is a new folder of its own, so Archive downloads never mix with the rest of the NAS: your own music and films, and the Grateful Dead library, which deadfetch/deadtag keep managing in `Music/GratefulDead*`.

- **R21. One root.** `root` is required. Every library, the inbox and the archive must resolve inside it (after following symlinks). A setting that points outside the root is a configuration error, and iafetch refuses to run. A path built from item metadata that would land outside it (see F15b) is refused too. The one exception is Grateful Dead items: the `deadtag` handler doesn't write them itself, but queues them with deadfetch, which keeps using its own folders (`Music/GratefulDead-Inbox` and the rest). iafetch writes nothing for them.
- **R22. The root must exist and be mounted.** As with deadtag's library, iafetch never creates the root itself. If `/mnt/synology/InternetArchive` is missing (an unmounted NAS, a typo), it stops and says so, rather than quietly creating a local folder. You create the root once by hand. iafetch creates the subfolders inside it as needed.

```toml
# ~/.config/iafetch/config.toml
root    = "/mnt/synology/InternetArchive"   # must exist; everything below lives inside it
inbox   = "_Inbox"      # relative paths are inside root
archive = "_Archive"    # original downloads kept after processing; omit to delete
acknowledged_terms = "2026-10-28"

[net]
rate = "4M"            # bandwidth cap, or "none"
concurrency = 1        # 1 to 4
api_pause = 1.0        # seconds, at least 1
download_pause = 2.0   # seconds, at least 1
torrent_over = "20G"   # offer torrents above this size (off unless watch_dir is set)
# torrent_watch_dir = "/mnt/synology/torrents/watch"

[large_job]
warn_bytes = "500G"
warn_items = 10000

[library]              # one folder per kind, inside root (these are the defaults)
movies     = "Movies"
tv         = "TV"
music      = "Music"
livemusic  = "Live Music"
radio      = "Radio"
audiobooks = "Audiobooks"
books      = "Books"
magazines  = "Magazines"
comics     = "Comics"
games      = "Games"
images     = "Images"
data       = "Data"
other      = "Other"

[handlers]             # collection -> handler; tried before the built-in rules
GratefulDead = "deadtag"
librivoxaudio = "audiobook"

[video]
quality = "h264"       # original | h264 | smallest
subtitles = true
nfo = true

[texts]
formats = ["pdf"]      # add "epub" for archive.org's OCR'd EPUBs
```

With those defaults, the NAS ends up like this:

```
/mnt/synology/InternetArchive/          created once by hand; iafetch makes the rest
├── _Inbox/                             downloads in progress (hidden .partial folders), then verified items
├── _Archive/                           original downloads, kept after processing
├── Movies/   Reefer Madness (1936)/Reefer Madness (1936).mp4, .srt, movie.nfo, poster.jpg
├── TV/       The Lone Ranger/Season 01/The Lone Ranger S01E01 - Enter the Lone Ranger.mp4
├── Music/  Live Music/  Radio/  Audiobooks/
├── Books/  Magazines/  Comics/
├── Games/  Images/  Data/
└── Other/                              anything the generic handler mirrors as-is
```

Adding these folders to Jellyfin as separate libraries (Movies and TV first) is optional and up to you. iafetch only writes the files and their `.nfo` metadata.

## 8. Command line (sketch)

```sh
iafetch search "prelinger nuclear" --kind movies --license pd
iafetch browse oldtimeradio
iafetch show OTRR_Gunsmoke_Singles            # files, what would be selected, size, license
iafetch queue add OTRR_Gunsmoke_Singles --episodes 1-52
iafetch queue add --catalog netlabels-ccby --top 20
iafetch queue list
iafetch get [--background] [--limit N] [--max-size 100G] [--dry-run]
iafetch status | dashboard
iafetch review                                  # list plans that need review
iafetch process <plan.json>                     # after editing a plan
iafetch verify <library-path>
iafetch catalog save netlabels-ccby 'collection:netlabels AND licenseurl:*by/*'
iafetch catalog update [name]
```

## 9. Phases

| Phase | Delivers | Done when |
| --- | --- | --- |
| **P1: Engine** | `net`, `api`, `select`, `download`, `queue`, `rights`, generic handler, deadtag adapter, `search`/`show`/`queue`/`get`/`status`, first-run notice | Downloads any unrestricted item verified; the R-tests pass (User-Agent always set, rate never exceeded, the breaker trips, restricted items refused); GD downloads behave exactly as deadfetch's |
| **P2: Media** | livemusic, music (netlabels, 78s), radio, video | A Prelinger film and a Classic TV season land in Jellyfin with NFOs; an OTR series is tagged by episode |
| **P3: Reading and listening** | audiobook (M4B), texts (PDF/EPUB/OPF, comics, magazines) | A LibriVox book plays in Audiobookshelf with chapters; a scanned book imports into Calibre with metadata |
| **P4: The rest** | software, images, torrent offload, TUI, dashboard | |

**Progress (2026-10-28):** `config` (R21, R22), `net` (R1-R7, R13), `api` (metadata cache, search with the restriction filter, F5), `select` (R10, R11, F7), `download` (F15, F15b, F15d, F16), `queue` (SQLite), `rights` (R14, R16-R18), the generic and deadtag handlers, and `search`, `show`, `queue`, `get` (with R19), `process`, `status`, `terms`. `video` (§6.7, from P2) is done too: one copy per video (the uploaded MP4, else archive.org's h.264; `[video] quality`), `.srt`/`.vtt` subtitles, films to `Movies/{title} ({year})/` with `movie.nfo` and `poster.jpg`, series to `TV/{series}/Season {ss}/` with `tvshow.nfo`, and the item's records in a hidden `.iafetch/<identifier>/`. Episodes are numbered from `SxxEyy`, `1x01` or a trailing number. Run-together names (`s01e01_EntertheLoneRanger`) give titles like "Enterthe Lone Ranger": the split isn't guessed. F8's `--episodes` isn't built; `--glob` selects episodes meanwhile. `texts` (§6.8, books part, from P3) is done: the searchable PDF (the uploaded Text PDF, else archive.org's Additional Text PDF; never the page scans), the EPUB only if `[texts] formats` asks (archive.org's are OCR'd), filed as `Books/{author}/{title} ({year})/` with Calibre's `metadata.opf` and `cover.jpg`. TOSEC title tags (`(1983)(Commodore)`) give the year and, failing a creator, the author. Magazines, comics and Gutenberg aren't handled yet. `queue add --search` queues every match of a query through the scrape API (R8), showing the count and size first and queuing only with `--yes`. `picks` ranks films linked to archive.org on Wikidata (P724, with their IMDb IDs, year, running time and copyright status) by IMDb's rating dataset, and shows each film's sharpest plausible upload (resolution and bitrate from archive.org's file metadata; an upload whose length, year or title disagrees is marked and never queued). By default only films Wikidata records as public domain in the US; `--any-rights` widens it. `--country` narrows it to a country of origin (P495); a country includes its earlier and divided states (Germany: Weimar, East and West Germany; Russia: the Soviet Union). `show` prints each video's resolution and bitrate. `software` (§6.9, from P4) is done: the program files (disk, tape and cartridge images, zips) exactly as published, the cover screenshot as `cover.jpg`, in `Games/{platform}/{title} ({year})/` (platform from the collections, the title or the emulator's file type), with the emulator settings in the record. A second copy of a book or game already in the library is filed beside it with its identifier in the folder name. archive.org's `history/` folders (replaced files) are never taken. Queuing a game also queues its English manual, if the platform's manuals collection has one (C64: `commodore_c64_manuals`, matched by title), filed in the game's folder as `Manual.pdf`; `queue manuals` does the same for games already queued, and `--no-manual` skips it. `queue remove --from <file>` removes many at once. `dashboard` (F12, from P4) is done, after deadfetch's: a page served on this computer (`--lan` for the home network, `--port`, `--html` for a snapshot) that refreshes every 3 s from the status file and the queue: the run's progress, speed and time left, what needs you, the library's folders with item counts, sizes and free space, and tables of the queue, filed items (with their covers) and failures, filtered by kind. Served on this computer it also has Start, Stop now and Stop after this item buttons (a per-page token and an Origin check guard them; with `--lan` it only watches). `iafetch start` (= `get --background`) and `iafetch stop` (`--after-current` to let the current item finish and be filed first) do the same from a terminal. `iafetch tui` (from P4) has two screens. **Choose**: a search, sent on Enter, fetches its results once with every filterable field (the scrape API returns them, 1,000 a request); three-state filters (include, exclude, neither) on kind, language, decade, format, collection and license, with counts, a words box (`+word -word "a phrase"` on title and subject), hiding what's queued or had, and four sorts then work locally with no more requests. Languages are merged ("eng", "English", "en") and a region tag in a title ("(DE)") wins over the field; favourites lists aren't collections. Tick items and queue them as `queue add` does. **Queue**: the waiting items in order; move (top, up, down, bottom), remove, retry failures, start and stop. Items have a position: `iafetch queue move`, and `get` reads the queue before each item, so changes take effect in a running download. Removing and clearing only mark items removed: `queue removed` lists them and `queue restore` (`--last` for the last removal, a whole clear included) puts them back where they were; `u` in the terminal UI's queue does the same. `queue export FILE` saves the waiting items with their options, handler and order; `queue import FILE` queues an export or a plain list of identifiers, checking restrictions again and skipping what's queued or (unless `--again`) downloaded. Still to do in P1: catalogs (F3) and `browse` (F2), SHA-1 checks (F15c: iacore checks MD5 only), the ramp-up and concurrency above 1 (downloads run one at a time), `verify` (F17) and `refresh` (F17a).

## 10. Decisions and open questions

Decided (2026-10-28):

- **Video first.** The first media handler is `video` (films and TV for Jellyfin). Music comes after.
- **Shared code is [iacore](https://github.com/wheidal/iacore)**, a separate public package (MIT) holding deadfetch's download engine. deadfetch uses it (merged into DeadShowTagger `main` at `ba79e3b`), and iafetch builds on it.
- **Our own client, not the official `internetarchive` library.** That library has no bandwidth cap, shared rate limiter or concurrency control, the parts that matter most here. Copy its good details instead (`cnt=0`, path guard, on-the-fly names, mtime skip; see [PRIOR_ART.md](PRIOR_ART.md)). Still read credentials from `ia.ini`, so they work with the official `ia` tool.
- **deadfetch's three gaps are fixed** (`cnt=0`, the `Content-Range` check, restarting on a 416), in DeadShowTagger `b612ca3`.
- **Everything goes under `/mnt/synology/InternetArchive`**, one subfolder per kind (§7, R21, R22).
- **The name stays `iafetch`.**

Still open:

1. **Contacting the Archive:** large mirrors (whole OTR or 78 rpm sets run to terabytes) cross the R19 threshold. Is that a use you have in mind? If so, an email to info@archive.org comes first.
2. **Jellyfin:** add `InternetArchive/Movies` and `InternetArchive/TV` as new libraries once the video handler works, or leave them out of Jellyfin?
3. **PDF metadata (deferred, 2026-10-28):** don't build a deadtag-style tool for books; existing tools cover it. If wanted later: when filing, call `exiftool` (optional, if installed) to write title and author into each PDF; leave library management and metadata lookup to Calibre (it reads our `metadata.opf`); put the archive.org-specific checks (checksum, page count against archive.org's scan count, a text layer via `pdffonts`) in `iafetch verify`, and point scan-only PDFs to OCRmyPDF. First check whether archive.org's PDFs actually carry poor metadata (`pdfinfo` on a few). Depends on whether books are read through Calibre or straight from the folders.
